# SemaPLC — 用自然语言写 PLC 程序

> 全球第一款集生成、验证、仿真于一体的开源 PLC 智能编程 IDE

---

## PLC 编程，为什么这么难

可编程逻辑控制器（PLC）是全球工业自动化的心脏——从工厂产线、电梯、交通灯，到发电厂和水处理厂，都在靠 PLC 运转。而 PLC 最常用的编程语言叫结构化文本（Structured Text，ST），它对大多数领域工程师来说晦涩难学，即使是老手，写完程序后想要验证它是否正确，也是一个漫长而痛苦的过程。

传统的 PLC 开发流程是这样的：

1. **编辑** — 在 PLC 编辑器里手写 ST 代码
2. **编译** — 调用编译器检查语法，报错了就改，改完再编
3. **部署** — 把程序烧到 PLC 硬件上
4. **调试** — 观察输入输出信号，人工判断逻辑对不对
5. **仿真** — 如果要看实际运行效果，还需要另外一套 SCADA 或仿真软件

这几个步骤散落在不同的工具里，改一行代码就要重新走一遍全流程。一个简单的控制逻辑，从写代码到确认它真的能跑，可能要花上大半天。

近年来，大语言模型（LLM）可以用自然语言生成 ST 代码，但问题同样没有解决：AI 生成的代码经常编译不过，或者编译过了但逻辑有错。更关键的是，**目前没有任何一款工具，能让你在同一个环境里生成代码、验证它是否正确、并且看到它运行起来是什么样子。** 你依然需要在多个工具之间反复跳转，手动拼凑出完整的开发闭环。

简单说：**写 PLC 程序，依然又慢、又累、又难信任。**

## SemaPLC：一句话改变一切

**说一句话，写一段程序，看一部动画 —— 全在浏览器里完成。**

SemaPLC 是一个完全开源的智能 PLC 开发环境。你只需要用自然语言描述你想要什么（比如"四层电梯：按下呼叫按钮，电梯开到对应楼层，开门三秒后关门"），剩下的全部交给 AI Agent：

- 它帮你**写** ST 代码
- 它帮你**编**译、部署到真实 PLC 运行时
- 它帮你**验**——不是只看语法，而是实际运行你的程序，检查它是否真的满足需求
- 验证失败了？它自动**改**，循环往复，直到一切通过
- 最后，它还在浏览器里**画**出一个与程序同步的工艺仿真动画，让你亲眼看到控制器在跑

你不需要离开浏览器，不需要连接硬件，不需要精通 ST 语法。你拿到手的，是一个经过验证的、可以立即运行的 PLC 程序。

## 闭环修复：从"生成"到"可信"

SemaPLC 的核心是一个自动闭环。Agent 生成 ST 代码后，不是直接交给你就结束了，而是进入一个自动修复循环：

```
自然语言需求 → 生成 ST → 编译 → 部署 → 行为验证 → 修复 → 重新编译 → …
                                   ↑                              │
                                   └──────── 失败则自动修复 ←──────┘
```

每一步失败都会触发自动修复：
- **编译失败** → Agent 读编译器报错，修改语法
- **行为测试不通过** → Agent 读运行时变量和测试报告，修改控制逻辑

循环直到程序编译通过且所有行为测试通过。你在聊天面板里可以实时看到 Agent 的每一步操作和修改记录。

这意味着什么？意味着你拿到的不再是"AI 猜的代码"，而是**经过真实 PLC 运行时验证过的、行为正确的程序**。

## 同步多视图：一种代码，三种看法

SemaPLC 在浏览器里同时展示程序的不同面貌，全部实时同步：

- **ST 代码编辑器** — 可以阅读、编辑，修改后自动重新编译和更新其他视图
- **梯形图（Ladder）视图** — 从 ST 自动推导生成，PLC 工程师最熟悉的继电器逻辑图
- **实时变量监控** — 每个 PLC 扫描周期刷新，可以直接"强制"某个输入来测试逻辑
- **工艺仿真动画** — SVG 渲染，变量驱动的实时动画，点击按钮就能和控制器交互

所有面板通过 WebSocket 保持同步。编辑代码，梯形图立刻更新；强制一个输入变量，仿真动画立刻响应。

## 行为验证：不止编译通过，更要行为正确

SemaPLC 不仅检查语法，更检查行为。Agent 会自动从你的需求中提取出一组行为测试场景，每个场景包含：
- **激励**：给 PLC 一组输入信号（比如按下某楼层的呼叫按钮）
- **断言**：检查运行后的变量是否符合预期（比如电梯到达该楼层、门打开了）

测试类型覆盖：
| 测试类型 | 电梯示例 |
|---------|---------|
| 到达检查 | 按呼叫 2，电梯到达 2 层并开门 |
| 原地操作 | 按呼叫 1（当前楼层），门开，电梯不动 |
| 顺序检查 | 按呼叫 3 再按呼叫 1，先到 3 后到 1 |
| 运动范围 | car_pos 在 [0, 300] 范围内，不卡住 |
| 定时检查 | 到达后约 3 秒自动关门 |
| 边沿触发 | 短按一下呼叫按钮，仍然正确 latch |

测试报告在几秒内返回，告诉你是通过还是失败，以及失败时变量在哪里偏离了预期。

## 工艺仿真：零硬件，看到控制器在跑

SemaPLC 的仿真引擎在浏览器内渲染一个 SVG 工艺场景——电梯、水箱、传送带、交通灯——全部由 PLC 的实时变量驱动。

以四层电梯为例：
- `car_pos` 变量驱动电梯轿厢的垂直位置
- `door_open` 变量控制门的开关动画
- `call_led` 变量点亮楼层呼叫按钮的 LED
- 点击楼层面板的呼叫按钮，直接注入 PLC 输入

你不需要 SCADA 软件，不需要真实硬件，打开浏览器就能看到控制器在跑。

## 模型无关 + 可复用工具链

**支持任意 LLM。** SemaPLC 的 Agent 基于 SemaCode 引擎构建，通过一个统一接口对接各种 LLM（DeepSeek、GPT、Claude ……）。换模型，改一行配置就行。

**工具链独立可用。** 编译器（MATIEC）、部署器（OpenPLC Docker）、变量读写、行为验证、仿真引擎——每个工具都同时支持 CLI 和 MCP 协议，可以脱离 IDE 独立调用，嵌入你自己的工作流或研究系统中。

```
┌─────────────────────────────────────────────────┐
│                  Web IDE（浏览器）                  │
│  ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐  │
│  │ 对话  │ │ ST   │ │ 梯形图│ │ 变量  │ │ 仿真  │  │
│  │ 面板  │ │ 编辑器│ │ 视图  │ │ 监控  │ │ 动画  │  │
│  └──┬───┘ └──┬───┘ └──┬───┘ └──┬───┘ └──┬───┘  │
│     └────────┴────────┴────────┴────────┘        │
│              （WebSocket 同步）                      │
├─────────────────────────────────────────────────┤
│              AI Agent（SemaCode）                 │
│         自然语言 → ST → 编译 → 验证 → 修复循环      │
├─────────────────────────────────────────────────┤
│           PLC 工具套件（CLI / MCP）                 │
│  编译(MATIEC) | 部署(OpenPLC) | 验证 | 仿真引擎    │
└─────────────────────────────────────────────────┘
```

## 效果数据：8 类任务，39/40 通过

在 8 类经典控制任务上进行端到端测试，每类任务跑 5 轮，共 40 轮：

| 任务 | 通过率 | 平均修复次数 | 代码行数 |
|------|--------|-------------|---------|
| 电机启停 | 5/5 | 0.2 | 42 |
| 急停控制 | 5/5 | 0.4 | 40 |
| 交通灯 | 5/5 | 2.0 | 46 |
| 停车场道闸 | 5/5 | 0.8 | 43 |
| 水箱液位（Bang-Bang） | 5/5 | 1.2 | 45 |
| 水箱液位（PID） | 5/5 | 1.0 | 38 |
| Pick-and-Place | 5/5 | 14.6 | 64 |
| 电梯 | 4/5 | 7.8 | 138 |

- 简单任务几乎一次就过
- 复杂任务需要更多修复，但最终都能通过
- 所有 8 个任务均成功生成浏览器内仿真动画
- 约一半的修复针对的是"编译通过但逻辑错误"的情况——这类错误没有行为验证根本发现不了

## 谁适合用 SemaPLC

### 🔧 工业自动化工程师
把书面需求快速变成经过验证的 PLC 程序，不必在编辑器、编译器、部署工具、仿真软件之间反复跳转。
